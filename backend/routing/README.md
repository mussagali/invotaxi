# Routing engine

`routing` — чистый детерминированный пакет без зависимостей от `app`, БД,
Redis, pandas/numpy/scipy. На вход `solve()` получает уже нормализованные
`OrderIn` (включая схлопнутых близнецов и итоговое число мест) и `DriverIn`.

## Стадии

Для каждого региона минивэны первыми строят рейсы до трёх заказов с полным
перебором посадок и высадок. Оставшиеся заказы вставляются в седаны с полной
пересборкой маршрута кандидата и эскалацией радиуса 2 → 5 → 10 → ∞ км.
Затем выполняется до четырёх раундов: транзакционная консолидация водителей с
малой загрузкой, повторная вставка, одиночный пулинг и групповой пулинг.
Остаток получает виртуальные арендные машины из центра тяжести подач; для них
также применяется минимальная загрузка. Последней стадией назначается обед из
наибольшего свободного разрыва, включая края окна 10:30–15:30, и запускается
независимый валидатор.

Консолидация не использует `deepcopy`: проверка идёт на легковесных копиях
списков неизменяемых `Block`, а коммит происходит только при переносе 100%
заказов распускаемого маршрута.

## API и конфигурация

```python
from routing import DriverIn, EngineConfig, OrderIn, solve

solution = solve(orders, drivers, EngineConfig())
assert solution.validation.is_valid
```

Все константы исходного движка находятся в `EngineConfig`: окно клиента,
service time, радиусы, min/max заказов, размер рейса, пороги пулинга, окно и
длительность обеда, скорость, winding factor, число и минимум арендных машин.
`EngineConfig.legacy()` отключает только новые проверки B1–B4 и предназначен
для сравнительного прогона, не для production.

Для дозаказа используется `online_insert(solution, new_order,
driver_positions)`. Для ещё не начавшего работу водителя расчёт начинается с
фактической `DriverPosition`, включая время доезда.

## Подмена DistanceProvider

Передайте реализацию протокола с методами `distance_km()` и `time_minutes()`:

```python
class OsrmProvider:
    def distance_km(self, lat1, lon1, lat2, lon2): ...
    def time_minutes(self, lat1, lon1, lat2, lon2): ...

cfg = EngineConfig(distance_provider=OsrmProvider())
```

Это единственная точка подмены встроенной модели haversine × 1.35 с двумя
берегами и двумя мостами. `bank_of()` кэшируется по координатам, округлённым до
пяти знаков.

## Сравнительный прогон

Команда: `python scripts/compare_engines.py`. Датасет — 250 заказов,
фиксированный `seed=42`, генератор тот же, что у golden-тестов.


На этом seed legacy назначает все 250 заказов, но O0096 и O0193 — тройняшковые
юниты по 6 мест — кладёт отдельными блоками в седаны вместимостью 4. Поэтому
валидатор возвращает два нарушения `capacity`. Режим с фиксами не допускает
эти назначения и оставляет без назначения 3 юнита: оба шестиместных юнита и
O0165, для которого после безопасного построения и консолидации маршрутов не
нашлось допустимой повторной вставки. Потеря трёх назначений корректна: итоговое
решение сохраняет точное покрытие через `unassigned` и имеет 0 нарушений вместо
полного, но физически невыполнимого legacy-расписания.
