# P7 — Realtime: WebSocket, уведомления

## Роль
Senior backend. Проект invotaxi-backend (P0–P6 готовы). Реалтайм-слой:
WebSocket для 1500 одновременных соединений через Redis pub/sub
(готовность к горизонтальному масштабированию API) + push-уведомления.

## Скоуп
1. `app/realtime/`:
   - `WS /api/v1/ws?token=...` — одно соединение на пользователя;
     аутентификация по access-токену ДО accept (иначе close 4401);
   - подписки по роли, сервер сам определяет каналы:
     driver → `driver:{id}`; client → `order:{id}` всех своих активных
     заказов; dispatcher → `dispatch:{district}` + live-карта;
   - один фоновый таск на процесс слушает Redis pub/sub (`psubscribe`)
     и раздаёт сообщения локальным соединениям; никакого состояния
     соединений вне процесса;
   - heartbeat ping/pong 30 с, мёртвые соединения закрываются;
     лимит: 3 соединения на пользователя (старое закрывается).
2. Типы событий (Pydantic-схемы, versioned envelope
   `{v:1, type, ts, payload}`):
   - `route.published` (водителю: его маршрут на день),
   - `route.updated` (водителю: перенос/дозаказ),
   - `order.status_changed` (клиенту),
   - `driver.position` (клиенту с активным заказом, throttle: не чаще
     1 раза в 3 с на заказ),
   - `plan.draft_ready`, `order.exception` (диспетчеру).
3. Публикация событий: единый `EventBus.publish(channel, event)` в
   `app/services/` — заменить прямые publish из P6 на него; вызовы из
   state machine (P3) при смене статусов.
4. Позиции водителей клиентам: фоновая задача раз в 3 с берёт из Redis
   позиции водителей, у которых есть активные заказы со слушателями
   (множество активных подписок хранить в Redis set), и публикует в
   `order:{id}`. Без слушателей — ничего не публикуется.
5. Push (FCM): `app/workers/push.py`, интерфейс `PushSender` +
   реализация FCM (ключ из ENV) + NoopSender для dev/тестов. Push
   шлётся, когда доставка по WS невозможна (нет активного соединения):
   route.published, order.status_changed(assigned/driver_en_route).
   Токены устройств: `POST /api/v1/devices {fcm_token, platform}`.

## Definition of Done
- [ ] интеграционный тест: два WS-клиента (водитель, клиент) →
      publish план → водитель получил route.published, клиент —
      order.status_changed
- [ ] WS без токена / с протухшим токеном → close 4401 (тест)
- [ ] клиент не может получать события чужого заказа (тест: подписка
      формируется сервером, канал левого заказа недоступен)
- [ ] событие, опубликованное «другим процессом» (напрямую в Redis),
      доходит до WS-клиента (тест — доказательство multi-process)
- [ ] throttle позиций: 10 обновлений за 3 с → ≤ 2 сообщения (тест)
- [ ] 4-е соединение того же пользователя закрывает 1-е (тест)
- [ ] локальный smoke: 500 параллельных WS-соединений (скрипт в
      tests/manual/, websockets lib) держатся 60 с без утечки памяти
      (приложить вывод RSS до/после)
