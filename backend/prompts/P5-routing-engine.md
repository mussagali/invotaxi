          cfg: EngineConfig) -> Solution
# Solution: routes[driver_id] -> list[Block(kind, order_ids,

## Что сохранить из оригинала (не «улучшать» без указания)
1. Стадийность: минивэны (рейсы по ≤3, полный перебор порядков
   посадки/высадки) → жадная вставка седанов с ПОЛНОЙ пересборкой
   маршрута кандидата и радиус-эскалацией 2→5→10→∞ → до 4 раундов
   {транзакционная консолидация водителей с < min_orders → повторная
   вставка → пулинг по одному → пулинг группами} → аренда (виртуальные
   машины из центра тяжести остатка) → обед из наибольшего разрыва.
2. Транзакционность консолидации: коммит только при размещении 100%
   заказов распускаемого водителя (реализовать без deepcopy —
   пересчёт на легковесных копиях списков блоков).
3. Время клиента ±15 мин — жёсткое ограничение, никакого расширения окна.
4. Гео-модель: haversine × 1.35, два берега (списки якорей из
   geo_utils.py перенести как есть), 2 моста, скорость 28 км/ч.
   Обернуть в `DistanceProvider` (protocol) — одна точка подмены на
   OSRM в будущем. Добавить lru_cache для bank_of по координатам,
   округлённым до 5 знаков.

## Баги, которые ОБЯЗАТЕЛЬНО исправить (из ревью оригинала)
- **B1 (критично):** вместимость по местам не проверяется в
  try_append_trip / build_sequential_route / try_build_run — близнецовый
  юнит на 4+ мест влезает в седан. Фикс: Trip — seats заказа ≤ capacity;
  Run — сумма seats группы ≤ capacity (проверка в момент формирования).
- **B2:** в pool_leftover_groups кандидаты `pool[:5]` берутся без
  сортировки по расстоянию — сортировать.
- **B3:** обед не рассматривает разрыв до первой и после последней
  поездки в пределах окна 10:30–15:30 — рассматривать.
- **B4:** rental_min_orders объявлен, но не применяется — после аренды
  прогонять ту же консолидацию по арендным машинам.
- **B5:** consolidate возвращает всегда пустой set — убрать мёртвый
  возврат, вернуть осмысленный отчёт (кого распустили).
- **B6:** пересборка маршрута обязана уважать уже назначенный
  route.lunch (для режима дозаказа) — блоки не могут пересекать обед.
- **B7:** режим `online_insert(solution, new_order, driver_positions)`:
  для водителя «ещё не в работе» учитывать время доезда от фактической
  позиции, а не телепорт к окну.
- Валидатор (`routing/validate.py`): дубли, окна ±15, bbox, И НОВОЕ —
  превышение вместимости в каждом блоке (в оригинале не проверялось).

## Тесты (pytest, покрытие routing/ ≥ 90%)

5. Перфоманс-гейт: 600 заказов / 40 водителей — solve() < 60 с на CI
   (без pandas это реалистично; профилируй, если не проходит).
