# P2 — Аутентификация и RBAC

## Роль
Senior backend. Проект invotaxi-backend (P0 каркас, P1 схема БД готовы).
Сделай авторизацию и ролевую модель. Роли: client, driver, dispatcher,
admin.

## Скоуп
1. `app/core/security.py`:
   - пароли: argon2 (passlib или argon2-cffi);
   - JWT: access 15 мин, refresh 30 дней; payload: sub(user_id), role,
     jti; алгоритм HS256, SECRET_KEY из конфига;
   - refresh-ротация: refresh одноразовый, jti хранится в Redis
     (`refresh:{jti}` с TTL), при использовании — инвалидация и выдача
     новой пары; повторное использование погашенного refresh →
     инвалидировать ВСЕ сессии пользователя (признак кражи токена);
   - logout: чёрный список access-jti в Redis до истечения TTL.
2. Эндпойнты `/api/v1/auth`:
   - `POST /login {phone, password}` → пара токенов + профиль;
     нормализация телефона (8/+7/7 → 10 цифр) как одна функция,
     переиспользуемая всюду;
   - `POST /refresh {refresh_token}`;
   - `POST /logout`;
   - `POST /users` (только admin/dispatcher) — создание пользователя
     любой роли с профилем (клиент/водитель);
   - `GET /me`.
3. Dependencies: `get_current_user`, `require_roles(*roles)` — использовать
   их во ВСЕХ будущих роутерах. Возврат 401 (нет/просрочен токен) vs
   403 (не та роль) — строго корректно.
4. Rate-limit на `POST /login`: max 5 попыток/мин на телефон+IP (Redis,
   sliding window), при превышении 429 + Retry-After.
5. Аудит: успешный/неуспешный логин → structlog с маскированным
   телефоном (7***…**45).

## Definition of Done
- [ ] login/refresh/logout/me работают (интеграционные тесты, httpx)
- [ ] повторный refresh тем же токеном → 401 и все сессии убиты (тест)
- [ ] access после logout → 401 (тест)
- [ ] эндпойнт с require_roles('dispatcher') отдаёт 403 клиенту (тест)
- [ ] 6-я попытка логина за минуту → 429 (тест)
- [ ] телефоны «87011234567», «+77011234567», «7011234567» дают одного
      пользователя (тест нормализации)
- [ ] пароли в БД только argon2-хэш; в логах нет пароля и полного телефона

Не делай: OTP/SMS (заглушка-интерфейс `SmsSender` с логированием —
достаточно), восстановление пароля — вне скоупа.
